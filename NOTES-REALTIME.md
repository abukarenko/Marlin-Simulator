## Как работает интерфейс

`src/MarlinHost.App/HostForm.cs`, локальная функция `Heater`:

- Изменение числа (`NumericUpDown.ValueChanged`) синхронизирует только ползунок. Команда не отправляется ни от набора числа, ни от стрелок поля, ни при уходе фокуса.
- Enter в числовом поле отправляет уставку.
- Отпускание кнопки мыши на ползунке отправляет уставку, если галочка нагрева включена. Изменение ползунка клавиатурой отдельно не обработано как отправка.
- Изменение галочки отправляет уставку или выключение нагрева. Просто оставленная включённой галочка не является кнопкой применения нового числа.
- Сопло: `M104 S...`; стол: `M140 S...`; это команды без ожидания достижения температуры.
- `Receive` читает фактическую температуру и уставку из ответа прошивки. Подпись `текущая / целевая` показывает телеметрию, числовое поле — пользовательский ввод; состояния «изменено», «ожидает», «подтверждено» нет.

Скорость / подача (`HostForm.cs`, группа `rates`):

- Число само по себе ничего не отправляет. Требуется отдельная кнопка ✓.
- Скорость: `M220 S...`; подача пластика: `M221 S...`.
- `Live` пишет «Команда: ...» ДО ожидания очереди и отправки. Такая запись ещё не означает передачу или подтверждение принтером.
- `PrintController.Speed/Flow` обновляются после завершения `link.Send`, но HostForm эти свойства не отображает.
- Запросы текущих коэффициентов не выполняются; опрос содержит только `M105`, `M114`, `M119`.
- При подключении коэффициенты контроллера начинаются со 100%, без чтения фактических значений прошивки.

## Как команды встраиваются в поток

`PrintController.Manual(script, live: true)` и `Run` используют один `SemaphoreSlim operation`.
Цикл файла захватывает его на одну команду и ждёт ответ. Между командами блокировка освобождается; есть `Task.Yield` для ожидающих действий и телеметрии.

Цепочка: элемент управления → `HostForm.Live` → `PrintController.Manual(..., true)` → ожидание `operation` → `Send` → `PrinterLink.Send` → нумерованная строка с checksum → ответ `ok` → обновление состояния контроллера.

- Live-команда вставляется в передаваемый поток; исходный G-code и `job.Commands` не изменяются. Счётчик прогресса файла её отдельно не учитывает.
- Разрешены `M104`, `M140`, `M106`, `M107`, `M220`, `M221` и команды опроса. Это общая последовательная очередь, без отдельной приоритетной очереди регулировок.
- В обычном исполнении допускается одна неподтверждённая команда Host. `busy` не завершает ожидание; требуется `ok` (тайм-аут 15 минут).
- Если текущая команда — `M109` / `M190`, новая уставка ждёт окончания нагрева. Аналогичная задержка возможна на `G28`, `G4`, `M400` и при заполненном планировщике. Немедленной коррекции уставки во время блокирующего ожидания сейчас нет.
- Обычный ввод команд / скриптов заблокирован при активном задании. Переключатели live обходят этот запрет только для списка разрешённых операций.
- Позднейшие `M104/M109/M140/M190/M220/M221` из файла могут снова изменить параметры: постоянного пользовательского переопределения нет.

## Что означает подтверждение

`PrinterLink.ProcessLine` завершает ожидание по `ok`. Обычный журнал скрывает отправку и `ok`; подробный показывает обмен.
Сообщение `Unknown command` выводится, но само по себе не переводит `Send` в ошибку, если прошивка затем прислала `ok`.
Поэтому запись в локальном состоянии после `ok` не заменяет чтение значения обратно из прошивки.

Включённые исходники Marlin:

- `Marlin/src/gcode/config/M220.cpp`: без параметров возвращает `FR:50%`; с `S` меняет `feedrate_percentage`.
- `Marlin/src/gcode/config/M221.cpp`: без `S` возвращает `echo:E0 Flow: 50%`; с `S` меняет коэффициент экструзии через `planner.set_flow`.
- `Marlin/src/module/motion.h`: `MMS_SCALED` применяет процент скорости к подаче движения.
- `Marlin/src/module/planner.cpp`: `e_factor` масштабирует шаги экструдера при формировании блоков.
- Это влияет на последующие планируемые движения; уже рассчитанные блоки не пересчитываются этими командами. Ответ `ok` не означает мгновенное изменение механической скорости.
- 50% скорости и 50% подачи: движение примерно вдвое медленнее при тех же прочих условиях, а пластика на тот же путь примерно вдвое меньше. Для простого замедления печати достаточно менять скорость; фактическая скорость также ограничивается ускорениями и пределами прошивки.

Форматы ответов выше подтверждены для включённой Marlin; у реального принтера версия и поддержка запросов требуют проверки.

## Дополнительный дефект паузы

`PrintController.ParkAndWait` запоминает уставки ДО паузы в локальные `nozzle/bed`.
Изменения температуры на паузе отправляются, но продолжение восстанавливает прежние уставки через `M190 R...` / `M109 R...` и присваивает их контроллеру.
Скорость и подача отдельно не восстанавливаются этим методом; пользовательские изменения сохраняются до следующей соответствующей команды файла.

## Предлагаемые исправления (ещё не реализованы)

1. Добавить явное применение температуры и различать введённое, ожидающее и подтверждённое значения. Отдельно определить поведение стрелок и завершения редактирования.
2. Для live-действий показывать состояния «в очереди», «отправлено», «подтверждено» / «ошибка»; при блокирующей команде объяснять задержку.
3. Показывать подтверждённые коэффициенты рядом с вводом; после `M220/M221` запрашивать значения обратно и разбирать ответы. Учитывать отсутствие поддержки в другой прошивке.
4. Добавить отдельную диагностику live-команд без необходимости включать полный поток `M114`.
5. Определить политику: последующие команды файла заменяют пользовательское значение или действует явное переопределение до конца задания.
6. При продолжении учитывать актуальные изменения температур на паузе.
7. Немедленное изменение температуры во время `M109/M190` проектировать отдельно: текущая очередь этого не обеспечивает; простой обход сериализации может нарушить сопоставление ответов и протокол.

## Покрытие проверками

Существующие `tests/MarlinHost.Tests/Program.cs` проверяют live M220/M221, повторную передачу и сохранение подачи при продолжении; нативная проверка также меняет коэффициенты на паузе.
Они не доказывают отправку от стрелок температурного поля, изменение температуры внутри M109/M190, чтение коэффициентов обратно или фактическую скорость механики.
Для будущего исправления нужны отдельные проверки этих сценариев, а также последующей команды файла и изменения температур на паузе.
